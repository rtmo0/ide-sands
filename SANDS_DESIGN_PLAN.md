Цель — интерфейс в духе [Orca](https://www.onorca.dev): плотный, тёмный, аккуратный, со статусами
агентов и песочниц на виду.

## Ориентир: что хорошо у Orca

- Почти чёрный фон; панели отделены тонкими границами, а не серыми плашками.
- Плотная мелкая типографика: основной текст 13px, вторичный приглушённый 11–12px; ветки, пути и
  идентификаторы — моноширинные.
- Статусы — точками и глифами (●, спиннер, чип «primary», счётчики), а не словами вроде «stopped».
- Один сайдбар слева: Projects → репозитории/worktree, у каждого подпись ветки и статус агента.
  Справа панель с вкладками-иконками (файлы, поиск, git, задачи). В центре вкладки агентов с
  иконкой состояния.
- Одна акцентная кнопка на экран, остальные действия — иконки.
- В статус-баре лимиты агентов: «5h 38% · wk 28%», время сброса.

## Что сейчас плохо (по скриншотам отладочной сборки)

1. Слева два списка проектов: Threads Sidebar Zed (обе песочницы подписаны «workspace») и наша
   Projects panel. Из-за этого кажется, что проекты не переключаются.
2. Дерево файлов и Sandbox panel делят правый док — виден только один. Центр после открытия
   проекта пустой.
3. Кнопки стиля `Filled` в текущей теме выглядят как обычный текст: главное действие не выделено.
4. Размеры шрифтов и отступы скачут; секции — серые плашки с крупным текстом.
5. Мастер нового проекта: форма в одну колонку, высота модалки меняется между шагами, нет
   степпера, ресурсы вводятся текстом.
6. Kubernetes: таблица схлопывается до нуля (автоширина колонок), вкладку зажимают боковые
   панели, навигация крупная.

## Этап 1. Основа: тема и общие компоненты

- Тема «Sands Dark» в стиле Orca: почти чёрный фон, тонкие границы, приглушённый вторичный текст,
  один акцентный цвет, цвета статусов. Открытый вопрос: делать её темой по умолчанию или оставить
  текущую тему пользователя и подстроить только компоненты.
- Общие компоненты в `sandbox_ui`:
  - заголовок секции, строка «ключ → значение», бейдж и точка статуса;
  - метр — полоска с процентом и подписью («сброс в 20:30»);
  - карточка-вариант (иконка, заголовок, описание), степпер, пустое состояние;
  - главная кнопка с акцентом.
- **Ползунок как в Docker Desktop** (в `ui` его нет): дорожка, перетаскивание, шаг, подпись
  значения и границ, клавиши ←/→. Использовать везде, где настройка — число в диапазоне
  (ресурсы песочницы и т. п.).

- Слева один сайдбар Projects (Threads Sidebar скрыт по умолчанию):

  - внутри — её репозитории с веткой моноширинным шрифтом, у основного пометка «primary»;
  - сверху «+ New Project».
- Справа панель с вкладками-иконками: Files, Search, Git, Sandbox, Kubernetes — дерево файлов

- Центр открытого проекта: экран проекта вместо пустоты — агент и его лимиты, репозитории,

- Статус-бар: лимиты агента «5h 38% · wk 28%», RAM песочницы, состояние подключения.

## Этап 3. Мастер нового проекта

- Шире, фиксированная высота, степпер «1 Sandbox → 2 Repositories → 3 Agent», футер с
  разделителем и акцентной кнопкой Next/Create.
- Сеть — три карточки (Allow all / Balanced / Deny all) с иконкой и описанием, под ними поле
  исключений.
- Ресурсы — ползунками:
  - CPU от 1 до числа ядер хоста;
  - память от 512 МБ до 75% RAM хоста, шаг 512 МБ (пределы `sbx create --memory`);
  - рядом вариант «Auto».
- Порты — чипы с «+».
- Репозитории — карточки (иконка, путь моноширинно, «primary»); добавление одной строкой с
  переключателем «Папка / Git URL».
- Агент — сетка карточек с иконками; к проекту подключается ровно один агент.

## Этап 4. Sandbox panel и статистика агента

- Шапка: имя, точка статуса, иконки старт/стоп/обновить. Секции без плашек.
- Ресурсы — метры CPU, RAM, диск (лимиты задаются при создании, здесь только показываются).
- Агент — лимиты 5h и неделя с процентом и временем сброса, стоимость, заполнение контекста.
  Источники данных:
  - Claude Code: JSON, который получает команда statusLine — поля
    `rate_limits.five_hour.used_percentage`, `rate_limits.five_hour.resets_at`,
    `rate_limits.seven_day.*`, `cost`, `context_window` (есть только у подписок Pro/Max и
    после первого ответа в сессии). Sands прописывает в песочнице `~/.claude/settings.json`
    statusLine, которая сохраняет JSON в файл, а панель его читает.
    Документация: https://code.claude.com/docs/en/statusline
  - Codex: `rate_limits` (primary/secondary: used_percent, окно, сброс) из событий
    `token_count` в `~/.codex/sessions/**/*.jsonl`.
- Компактные Toolchains, Ports, Network.

## Как проверять

- Каждый экран — скриншот до и после, сценарии прокликиваются (у Studio Code есть права Screen
  Recording и Accessibility). Снимок окна: `screencapture -x -o -l <window id>`; клики и ввод —
  маленькая утилита на Swift через CGEvent; приложение выводить вперёд через System Events,
  иначе клики уходят в окно позади.
- Запуск отладочной сборки: `cargo build -p sands --features gpui_platform/runtime_shaders`
  (без Metal Toolchain), запускать с `PATH`, где есть `cargo` и `cargo-zigbuild` — remote server
  собирается из исходников. Первое подключение к каждой песочнице закачивает ~475 МБ и идёт
  минутами.
- Тестовая песочница `sands-k8s-lab`: kind-кластер (web, broken, tick, Helm-релиз demo).
  Для kind внутри песочницы нужны `/dev/null` смонтированный как `/dev/kmsg` и загрузка образов
  через `docker save --platform linux/arm64 | ctr -n k8s.io images import -`.
- Один этап — один коммит в `main`.
